\section{Getting Started}
In this tutorial we use \ty{alfy} to analyze simulated and real
data. To get started, we need to make sure the dependencies are met.
Apart from the programs in the Alfy repo, this tutorial depends on the
coalescent simulator \ty{ms}, the program \ty{ms2dna} for converting
the output of \ty{ms} to DNA sequences, local Blast, and the programs
of the Biobox repo. Table~\ref{tab:dep} shows where to get these
programs. Make sure they are all in your ``path''.

\section{Simulated Data}
We begin by simulating single crossover events before we generalize
this to multiple crossovers.
\subsection*{Single Crossover}
The program \ty{cross.sh} simulates single crossovers between two
subject sequences to generate one query sequence. By default, the
three sequences are 10\,kb long and the crossover event is in the
middle. So we get the result illustrated in Figure~\ref{fig:hom},
where the first 5\,kb of the query are more closely elated to $s_1$,
the rest is more closely related to $s_2$. We print the help message
of \ty{cross.sh}
#+end_export
#+begin_src sh <<sda.sh>>=
  bash cross.sh -h
#+end_src
#+begin_export latex
\begin{verbatim}
Usage: bash cross.sh [-h] [option]...
Simulate single midpoint crossover between one
   query and two subjects in q.fasta and s.fasta.
Example: bash cross.sh -s 3
   -l int
        sequence length (default 10000)
   -s int
        seed (default random integer)
\end{verbatim}

\subsection*{Multiple Crossovers}
The simulation scenario implemented in \ty{cross.sh} is rather
simple. For a more thorough exploration of \ty{alfy} we need to be
able to simulate more diverse datasets. Figure~\ref{fig:wf} shows our
workflow for this. It starts with population genetic parameters, which
are transformed by the script \ty{neiSim.sh} into haplotypes in
\ty{haplotypes.ms}, a corresponding query sequence in \ty{query.fasta}
and two or more corresponding subject sequences in
\ty{subjects.fasta}. From the sequence data \ty{alfy} calculates the
observed annotations, while \ty{ms2nn} extracts the expected
annotations from the haplotypes. Finally, the observed and expected
results are compared to calculate the accuracy, $a$.

\begin{figure}[ht]
  \begin{center}
    \input{../tut/wf}
  \end{center}
\caption{Workflow for calculating the accuracy, $a$, of \ty{alfy}
  (red); auxiliary programs in blue.}\label{fig:wf}
\end{figure}

In the following, we first familiarize ourselves with the individual
steps of the workflow in Figure~\ref{fig:wf}, before we summarize them
into the script \ty{testAlfy.sh}. We begin by printing the help
message of \ty{neiSim.sh}.

#+begin_src sh <<sda.sh>>=

#+end_src
#+begin_export latex

We run \ty{neiSim.sh} with default options, which in particular means
no recombination, except for the seed for the random number generator,
which we set to 1 to make the simulation reproducible.
#+end_export
#+begin_src sh <<sda.sh>>=
  bash neiSim.sh -s 1
#+end_src
#+begin_export latex
When we run \ty{alfy} on the query and subject sequences we just

#+end_export

neighbor, the program \ty{ms2nn} also tells us that sequences 1 and 3
differ at 0.0006 positions per site. For our 10\,kb sequence this
implies six mismatches.

It is well known that local fluctuations in the mutation density can
lead to local fluctuations of nearest neighbors even in the absence of
recombination. With Blast we can see that the local annotations of
\ty{alfy} are correct four out of five times in this particular
example.
#+end_export
#+begin_src sh <<sda.sh>>=
  printf "Alfy\tBlast\n"

      while read start end score anno; do
	  printf "$anno\t"

#+end_export

#+begin_export latex

#+end_export
#+begin_export latex

#+end_export

annotated query positions as implemented in the Awk script
\ty{accuracy.awk}. We apply this to our expected and observed results to

#+begin_src sh <<sda.sh>>=

\section{Real Data}
Our analysis of real data is centered on HIV genomes. We annotate the
query strain \ty{A+\-DQ\-083238} using the 42 pure strains stored in
\ty{hiv42.fasta} as subject.
#+end_export
#+begin_src sh <<eda.sh>>=
  cp ../data/A+DQ083238.fasta .
  cp ../data/hiv42.fasta .
#+end_src
#+begin_export latex
We analyze the query with \ty{alfy}.
#+end_export
#+begin_src sh <<eda.sh>>=
  alfy -i A+DQ083238.fasta -j hiv42.fasta
#+end_src
#+begin_export latex
\begin{verbatim}
>A+DQ083238
1       225       8.6   A1+AF004885
226     495      25.1   A1+AF069670
...
8806    9330      8.9   A1+AF004885
9331    9699     15.8   A1+U51190

This means that positions 1--225 of A+DQ083238 are most closely

The program \ty{alfy} works in three steps:
\be
\I Construct enhanced suffix array from all query and
subject sequences;
\I determine ``winning'' subjects across contiguous intervals
along a query;
\I carry out sliding window analysis of these closest neighbors intervals to
find the final annotation of a given query.
\ee
The last step is sensitive to the length of the sliding window. By
default this is 300 bp; if we set it to 400 bp, the results
change somewhat, but not dramatically.
#+end_export
#+begin_src sh <<eda.sh>>=
  alfy -w 400 -i A+DQ083238.fasta -j hiv42.fasta  | 
      sed 's/+.*//' | 
      awk -f quantifyGenotypes.awk
#+end_src
#+begin_export latex
\begin{verbatim}
>A
A1  63.1
C   26.8
G   7.6
D   2.5
\end{verbatim}

We may only be interested in ``strong'' homology signals in our
analysis. These are defined as regions where the average shustring
length is greater than the maximum shustring length occurring by
chance alone. Regions with an average shustring length below the
threshold value are marked \ty{nh} for ``no homology''.
#+end_export
#+begin_src sh <<eda.sh>>=
  alfy -i A+DQ083238.fasta -j hiv42.fasta -M
#+end_src
#+begin_export latex
\begin{verbatim}
>A+DQ083238
1       225       8.6   A1+AF004885
226     495      25.1   A1+AF069670
...
8836    9330      9.1   A1+AF004885
9331    9699     15.8   A1+U51190
\end{verbatim}

As before, we summarize the annotations and find that the K annotation
is now missing altogether and 8.7\% of the annotations are revealed as
``weak'' (\ty{nh}).
#+end_export
#+begin_src sh <<eda.sh>>=
  alfy -i A+DQ083238.fasta -j hiv42.fasta -M |
      sed 's/+.*//' |

A+DQ083238  J+AF082395   87.838  74   9   0   1  74   5877  5950  1.72e-19  87.9

The amount of weakly homologous regions is sensitive to the minimal
length of a recombining fragment. This quantity is set by the \ty{-f}
option with a default value of $\ty{-w}/4=75$. Increasing this value
leads to fewer regions diagnosed as ``non homologous''. For example,
if we double the value of \ty{-f}, we get none.
#+end_export
#+begin_src sh <<eda.sh>>=
  alfy -f 150 -i A+DQ083238.fasta -j hiv42.fasta -M |
      sed 's/+.*//' | 
      awk -f quantifyGenotypes.awk
#+end_src
#+begin_export latex
\begin{verbatim}
>A
A1  64.0
C   24.7
G   8.5
D   2.8
\end{verbatim}

The previous result is again sensitive to the parameter settings. In
this case the central quantity is the significance value for the
maximum shustring length. The mathematical theory for this was derived
in~\cite{hau09:est} and it is set with the \ty{-P} option. This can be
interpreted like a classical $P$-value: it is the error probability
when rejecting the null hypothesis that a shustring of some given
length is due to chance alone. The default value of the \ty{-P} option
is 0.4, which may strike you as rather high---why not use the
classical $P=0.05$ threshold? It is important to realize that a query
has to contain not just one shustring that is longer than the maximum
shustring length, but this property has to apply on average to
\textit{all} shustrings across a given window. If we set \ty{-P} to a
much more stringent value like 0.05, almost a quarter of the query is
annotated as non-homologous, most likely an overestimate.
#+end_export
#+begin_src sh <<eda.sh>>=
  alfy -i A+DQ083238.fasta -j hiv42.fasta -M -P 0.05 | 
      sed 's/+.*//' | 
      awk -f quantifyGenotypes.awk
#+end_src
#+begin_export latex
\begin{verbatim}
>A
A1  44.2
nh  23.8
C   22.7
G   6.3
D   2.9
\end{verbatim}
#+end_export
